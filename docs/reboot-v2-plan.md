# 棋妙英雄 v2 重制计划

## 目标

在保留“六角棋盘连跳 + Roguelite 成长”核心体验的前提下，降低代码耦合、统一视觉语言，并建立可持续替换美术资产的工程入口。

## 当前审计结论

- 正确的开发基线是 `master`；`main` 只包含一次脚本备份。
- 工程为 UrhoX + Lua 5.4，竖屏短边设计宽度为 480。
- 现有玩法已经完整，但脚本总量约 4.5 万行；`BoardWidget_VFX.lua`、`BoardWidget.lua`、`Battle.lua` 是首批拆分目标。
- `Battle.lua` 已拆出 `BattleEnemy.lua` 和 `BattleSpawn.lua`，说明注入式子模块是当前工程可接受的迁移方式。
- `GameState.lua`、运行时延迟 `require` 与 UI/战斗双向依赖形成主要耦合点。
- 当前视觉同时使用像素 UI、半写实 Boss、卡通企鹅、3D 质感图标和章节插画，单个资产质量不低，但整体不像同一套产品。
- 仓库已有约 1,000 个资产及元数据文件。重制应采用“目录并存 + 显式映射 + 分批切换”，不原位覆盖。

## v2 代码分层

```text
App
├── bootstrap       启动、生命周期、平台事件
├── presentation    UI、主题、棋盘绘制、VFX、音频
├── application     回合流程、关卡流程、菜单导航
├── domain          棋盘规则、战斗规则、技能、装备、敌人
└── infrastructure  存档、平台接口、资源目录
```

### 第一阶段：建立边界，不改玩法

1. 将全局 UI 主题和缩放配置从 `main.lua` 抽到 `UITheme.lua`。
2. 为棋盘渲染、战斗逻辑和回合流程建立依赖方向图。
3. 对大文件按职责继续拆分，优先拆纯函数和数据表。
4. 保持旧存档结构和当前发布入口兼容。

### 第二阶段：可测试的领域层

1. 把六角坐标、移动、跳跃和伤害计算整理为不依赖 UI 的模块。
2. 给核心规则增加 Lua 单元测试夹具。
3. 将全局状态逐步替换为显式 `GameSession` 上下文。

### 第三阶段：表现层换皮

1. 锁定一套画风锚点和 Game Bible。
2. 新资产写入 `assets/v2/`，保留旧资源作为回退。
3. 先替换主角、基础敌人、六角格、HUD、技能图标，再替换章节与 Boss。
4. 每一批资产同时验证 480 设计宽度、长屏安全区和战斗可读性。

## 美术资产批次

| 批次 | 内容 | 目标 |
|---|---|---|
| A | 主角、史莱姆、骷髅、六角格、移动/攻击高亮 | 先验证核心关卡是否像同一个游戏 |
| B | HP、金币、回合、目标、确认/撤销按钮 | 建立 HUD 组件语言 |
| C | 15 个技能和 6 阶连击奖励图标 | 统一轮廓、材质和稀有度表达 |
| D | 五章普通敌人、地形和道具 | 扩充世界但不改变基础造型规则 |
| E | Boss、章节主视觉、商店和装备 | 处理高成本内容与商业化页面 |
| F | Logo、商店截图、封面和宣传图 | 最后统一品牌传播资产 |

## 画风确认关

先用完全相同的第 1 章核心关卡构图制作三张候选：

1. 精致低细节 2D 卡通：低成本、战斗可读性最强。
2. 欧美 3D 渲染转 2D：商业完成度高，资产成本较高。
3. 统一像素复古：延续当前方向，但角色、UI 与场景必须共用同一像素网格。

只在用户确认其中一个方向后，才开始批量生成和接入正式资产。

## 保留与替换原则

- 保留：玩法数据、章节机制、音频中仍符合节奏的部分、现有存档。
- 分批替换：角色、敌人、章节图、HUD、技能/装备图标。
- 暂不删除：所有被脚本或 `.project/resources.json` 引用的旧资源。
- 禁止直接覆盖：新资产使用带 `v2` 的稳定文件名，确认接入后再清理旧版本。
