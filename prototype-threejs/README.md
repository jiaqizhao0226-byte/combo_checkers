# 棋妙英雄 Three.js 重制原型

这是棋妙英雄的纯 Three.js 重制分支。角色、棋盘和环境全部由代码生成，不依赖外部模型或贴图；同一套 3D 模块同时服务浏览器视觉原型和微信小游戏原生入口。

## 技术结构

```text
game.js                    微信小游戏原生入口（wx canvas，无 DOM）
game.json                  微信小游戏配置
index.html                 浏览器视觉原型入口
model-review/              与正式战斗隔离的第一章小怪模型验收台
src/core/HexRules.js       与平台无关的六角格规则
src/core/ChapterOneData.js 第一章关卡、敌人、连击与技能数据
src/core/LevelOne.js       与平台无关的第一章战役状态机
src/game/                  Three.js 棋盘、角色、环境和材质
src/wechat/HudOverlay.js   微信小游戏 CanvasTexture HUD
tests/level-one.test.mjs   第一章关键规则回归测试
vendor/                    本地 Three.js ESM，避免运行时 CDN
```

生产方向固定为 JavaScript/TypeScript + Three.js + 薄平台适配层。React 不是微信小游戏运行所需，也没有放进渲染主循环。

## 浏览器运行

在仓库根目录启动只绑定本机的静态服务器：

```bash
python3 -m http.server 8260 --bind 127.0.0.1
```

小怪模型验收页使用同一套 Three.js 模型代码，但不会触发正式战斗逻辑：`/model-review/`。

然后打开 `http://localhost:8260/prototype-threejs/`。必须通过静态服务器访问，`file://` 会拦截 ES module。

## 微信小游戏运行

目录已经满足小游戏入口结构，可通过已配置的 `weixin-minigame-helper` MCP 对本目录执行 `run_game`。当前已在其微信兼容沙箱中验证：

- Three.js r185 成功打包与持续渲染；
- 61 格棋盘、程序化角色、阴影、森林场景和 Canvas HUD 正常显示；
- 不依赖 `window`、`document`、HTML 或 CSS；
- `wx` 触控、前后台生命周期和同步本地存储已接入。

核心规则回归测试：

```bash
for test_file in prototype-threejs/tests/*.test.mjs; do node "$test_file" || exit 1; done
```

真机预览、分包体积、低端机帧率与微信审核仍需在取得对应 AppID/私钥后单独验证；沙箱通过不等于已经完成正式上架验收。

## VFX 测试模式

`src/vfx/VfxTestConfig.js` 里的 `VFX_TEST_MODE` 是测试入口总开关：

- `true`：局内底部显示“特效测试”入口；点击后打开独立测试台，可分别触发各个候选效果，也可清空当前特效。
- `false`：隐藏测试 UI 并禁止测试触发，正式打包前应保持此值。

测试效果由 `src/vfx/VfxDirector.js` 独立管理，不修改关卡数值、敌人生命或回合状态。`APPROVED_BATTLE_VFX` 是正式战斗白名单，默认保持为空；新效果必须先在本地测试台验收，得到明确确认后才可以把对应 id 加入白名单。未批准的效果即使已经有代码，也不会由真实战斗事件触发。

攻击特效遵循动作语义：刀光沿攻击与受力方向展开，接触点只出现短促爆点和定向碎屑；连击按实际次数依次显示刀痕后再收束。只有震地、冲击波等范围技能使用环形扩散，普通攻击不使用半圆或范围环。

## 局内镜头规则

`src/game/BattleCameraController.js` 将三类镜头意图分开处理：

- 双指缩放保存为用户的绝对基础倍率，不再绑定某一帧的自动缩放状态；
- 规划时只取企鹅、路线和当前有效落点；移动时企鹅留在安全区内镜头不动，接近边缘后才逐帧跟随其地面投影，连跳之间保持同一镜头运动，不按格子切换或随起跳上下晃；
- 敌方回合的普通移动不会抢镜；仅在攻击者位于屏幕外，或远程攻击跨出安全画面时临时调整构图；
- 临时拉远结束后延迟恢复近景，并用屏幕安全区、跟随死区和带速度连续性的阻尼减少镜头抽动。
