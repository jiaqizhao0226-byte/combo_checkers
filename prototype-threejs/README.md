# 棋妙英雄 Three.js 重制原型

这是棋妙英雄的纯 Three.js 重制分支。角色、棋盘和环境全部由代码生成，不依赖外部模型或贴图；同一套 3D 模块同时服务浏览器视觉原型和微信小游戏原生入口。

## 当前完成度

- 相邻移动、对称长跳、连续跳跃规划、点当前落点确认，以及无后续跳跃时自动执行；规划落点带呼吸确认环。
- 沿用旧版 Lua 数值：企鹅 100 HP / 15 攻击 / 1 防御，史莱姆 25 HP / 5 攻击。
- 连击伤害按 `15 × (1 + (combo - 1) × 0.5)` 递增。
- 首次 1-1 的五步聚光实操教程：移动、基础跳跃、远距跳跃、二连跳两段落点和首次连击奖励；教程完成后持久化，再次挑战时以 7 只史莱姆开局。
- 原版敌方追击/攻击顺序、偶数回合外围增援、各关击杀目标、战场道具和金币掉落。
- 原版回合时序：玩家动作与动画结算后进入敌方前摇；史莱姆回合开始时贴身则攻击，否则只移动一格且不会移动后立刻攻击。

- 每关胜利后三选一升级，19 个原版基础技能会跨关保留并进入伤害、吸血、护盾、控制、反伤、标记、陷阱等真实战斗公式；雷震天罚、血棘共生、猎杀本能、焚身狂战、碎片雷区 5 个组合技也会按等级和触发。

- 浏览器入口 `index.html` 与微信小游戏入口 `game.js` 共用棋盘、角色、材质和环境模块。

## 技术结构

```text
game.js                    微信小游戏原生入口（wx canvas，无 DOM）
game.json                  微信小游戏配置
index.html                 浏览器视觉原型入口
model-review/              第一章小怪模型源与本地验收台（模型源与正式战斗共用）
vfx-review/                连击与战斗特效的竖屏本地验收台（与正式效果模块共用）
src/core/HexRules.js       与平台无关的六角格规则
src/core/ChapterOneData.js 第一章关卡、敌人、连击与技能数据
src/core/LevelOne.js       与平台无关的第一章战役状态机
src/game/                  Three.js 棋盘、角色、环境和材质
src/game/AbyssTrenchEnvironment.js 第一章深渊海沟外围场景
src/wechat/HudOverlay.js   微信小游戏 CanvasTexture HUD
tests/level-one.test.mjs   第一章关键规则回归测试
vendor/                    本地 Three.js ESM，避免运行时 CDN
```

生产方向固定为 JavaScript/TypeScript + Three.js + 薄平台适配层。React 不是微信小游戏运行所需，也没有放进渲染主循环。

## 浏览器运行

在仓库根目录启动只绑定本机的静态服务器：

```bash
python3 -m http.server 8260 --bind 127.0.0.1
```

小怪模型验收页使用正式战斗共用的 Three.js 模型代码，但不会触发关卡或战斗逻辑：`/model-review/`。

然后打开 `http://localhost:8260/prototype-threejs/`。必须通过静态服务器访问，`file://` 会拦截 ES module。

## 微信小游戏运行

目录已经满足小游戏入口结构，可通过已配置的 `weixin-minigame-helper` MCP 对本目录执行 `run_game`。当前已在其微信兼容沙箱中验证：

- Three.js r185 成功打包与持续渲染；
- 61 格棋盘、程序化角色、阴影、森林场景和 Canvas HUD 正常显示；
- 不依赖 `window`、`document`、HTML 或 CSS；
- `wx` 触控、前后台生命周期和同步本地存储已接入。

核心规则回归测试：

```bash
for test_file in prototype-threejs/tests/*.test.mjs; do node "$test_file" || exit 1; done
```

### 正式发布包基线

不要把整个开发目录直接提交。由固定脚本生成只含运行依赖、关闭测试入口并完成包体检查的发布目录：

```bash
node prototype-threejs/tools/build-wechat-release.mjs --version 0.1.0
```

- 发布目录：`dist/wechat-release/`
- 发布清单：`dist/wechat-release.manifest.json`
- 当前结构：2.65 MiB 主包 + 2.25 MiB 主界面音频分包 + 8.69 MiB 战斗音频分包，总计 13.59 MiB；距离构建红线仍有约 1.35 MiB 主包余量和 6.41 MiB 总包余量。
- 首屏只加载主界面音频；进入战斗时再加载战斗音频。
- 构建会强制关闭 `VFX_TEST_MODE`，排除测试、验收页、HTML 和 source map，并在超出主包或总包红线时失败。

完整说明和提审前检查见 [`RELEASE_BASELINE.md`](./RELEASE_BASELINE.md)。当前已用微信小游戏运行器验证三包打包、主界面、进入战斗和两个音频分包加载；真机性能与审核仍需在取得对应 AppID/私钥后验证，沙箱通过不等于已经完成正式上架验收。

## VFX 测试模式

`model-review/` 和 `vfx-review/` 是长期开发资产，不是接入完成后即可删除的临时目录。今后的模型、独立动作与特效仍需先在对应验收台确认，再进入正式战斗。发布构建可以排除测试页面以控制包体，但不得从源码工程中删除这两个验收台。

`src/vfx/VfxTestConfig.js` 里的 `VFX_TEST_MODE` 是测试入口总开关：

- `true`：局内底部显示“特效测试”入口；点击后打开独立测试台，可分别触发各个候选效果，也可清空当前特效。
- `false`：隐藏测试 UI 并禁止测试触发。开发源码可以继续使用 `true`，正式构建脚本会在独立发布目录中强制改成 `false`，不需要为了发布修改开发环境。

开发测试台还包含“技能三选一”界面预览，用于在微信竖屏安全区内检查技能卡字号、说明换行和触控区域；预览不会授予技能或修改关卡状态。正式关卡胜利与幸运轮盘的额外技能选择共用同一套卡片组件。

测试模式下，局内“教程”第一页还提供“重播开场聚光引导”。它会建立一份独立的 1-1 教程预览状态，不清除或覆盖玩家已经完成的教程存档；每一步只开放当前聚光灯内的棋盘落点，聚光灯外的棋盘和 HUD 点击都会被拦截。

测试效果由 `src/vfx/VfxDirector.js` 与 `src/vfx/ComboRewardDirector.js` 管理。`APPROVED_BATTLE_VFX` 是正式战斗白名单；当前包含近战命中、伤害数字、主角受击反馈，以及已经验收的 2 至 8 连完整演出。测试面板预览不修改关卡数值；正式战斗只在核心规则产生相应奖励事件时触发同一套演出。

攻击特效遵循动作语义：刀光沿攻击与受力方向展开，接触点只出现短促爆点和定向碎屑。连击不是统一递进或统一收束特效，而是按 2 至 8 连分别触发追踪飞镖、稻草人、六芒冲击波、生命虹吸、时间静止、流星火雨和绝对反射。只有震地、冲击波等范围技能使用环形扩散，普通攻击不使用半圆或范围环。

## 局内镜头规则

`src/game/BattleCameraController.js` 将三类镜头意图分开处理：

- 双指缩放保存为用户的绝对基础倍率，不再绑定某一帧的自动缩放状态；
- 规划时只取企鹅、路线和当前有效落点；移动时企鹅留在安全区内镜头不动，接近边缘后才逐帧跟随其地面投影，连跳之间保持同一镜头运动，不按格子切换或随起跳上下晃；
- 敌方回合的普通移动不会抢镜；仅在攻击者位于屏幕外，或远程攻击跨出安全画面时临时调整构图；
- 临时拉远结束后延迟恢复近景，并用屏幕安全区、跟随死区和带速度连续性的阻尼减少镜头抽动。
