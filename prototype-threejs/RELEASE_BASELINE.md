# 微信正式发布包基线

更新时间：2026-08-21

这份基线用于从开发目录生成一个可以导入微信开发者工具的干净发布目录。开发目录继续保留本地模型、特效验收页和测试开关；正式包只收集 `game.js` 实际依赖的运行代码，不直接上传整个 `prototype-threejs/`。

## 生成方式

在仓库根目录运行：

```bash
node prototype-threejs/tools/build-wechat-release.mjs --version 0.1.0
```

输出：

- 微信开发者工具导入目录：`dist/wechat-release/`
- 文件清单、SHA-256 与包体统计：`dist/wechat-release.manifest.json`

`manifest` 放在上传目录外，不会随小游戏代码一起上传。

## 当前分包结构

| 包 | 内容 | 当前大小 | 微信红线 |
| --- | --- | ---: | ---: |
| 主包 | 游戏代码、Three.js、程序化模型与场景 | 2.48 MiB | 4 MiB |
| `audio-menu` | 主界面音乐与短音效 | 2.25 MiB | 普通分包 |
| `audio-battle` | 普通战斗、平静战斗与 Boss 音乐 | 8.69 MiB | 普通分包 |
| 合计 | 主包与两个分包 | 13.42 MiB | 20 MiB |

当前主包余量约 1.52 MiB，总包余量约 6.58 MiB。构建会在任一红线被突破时直接失败。

分包按使用时机加载：首屏只请求 `audio-menu`；玩家点击“开始冒险”后才请求体积较大的 `audio-battle`，不在启动阶段后台下载整包战斗音乐。

## 构建时自动执行的发布保护

- 强制把 `VFX_TEST_MODE` 改为 `false`，正式包不出现“特效测试”入口。
- 排除 `tests/`、`vfx-review/`、本地 HTML 验收页和 source map。
- 仅沿 `game.js` 的本地模块依赖生成主包，避免模型验收台等开发文件误入发布包。
- 生成 `game.json` 的两个普通音频分包声明。
- 生成面向小游戏的 `project.config.json`，关闭上传 source map 和热重载。
- 校验主包、总包、发布配置、测试开关和禁止文件，并为每个文件记录 SHA-256。
- 不写入 AppID、上传私钥或任何本机凭证。

## 已完成验证

- 全部 19 组本地回归测试通过。
- 微信小游戏运行器识别为 3 个包：主包、`audio-menu`、`audio-battle`。
- 正式包主界面成功渲染，点击“开始冒险”后成功进入第一关棋盘。
- 运行日志确认两个音频分包均成功加载，未出现游戏代码错误。
- 正式包中未出现局内特效测试按钮。

## 真正提交审核前仍需完成

1. 使用正式 AppID 在微信开发者工具导入 `dist/wechat-release/`。
2. 做真机预览，覆盖至少一台低端 Android、一台主流 Android 和一台 iPhone。
3. 验证首次启动、弱网进入战斗、音频分包失败重试、前后台切换、静音开关、触控与安全区。
4. 记录首屏时间、战斗稳定帧率、峰值内存和崩溃日志。
5. 补齐隐私、网络域名、云能力、版本号和审核资料后，才执行上传与提审。

当前基线只生成并验证本地正式包，没有上传开发版、体验版或审核版。
