# Three.js 角色建模准则

这份文件记录 `Combo Checkers` 模型验收中已经确认的经验，后续可整理为可复用的 Three.js 建模 Skill。

## 1. 主体必须先形成连续体

- 头、躯干、脸罩、腹部等大体块要共享连续、可信的轮廓关系。
- 不用额外球体或薄片模拟本应属于主体表面的反光、肤色或普通斑纹。
- 接缝必须顺着主体曲率，不能悬浮、穿插或像橡皮泥贴块。
- 只有真正独立的解剖结构、硬质装甲或装备才使用独立网格。
- 尾巴、翅膀、四肢等独立结构的根部必须埋入主体，并延续主体材质与轮廓，不能在连接处露出完整截面。
- 默认禁止没有物理连接的悬浮零件；只有骷髅、幽灵、法术、磁悬浮机械等被明确设定为分离结构的设计可以例外。
- 关节枢轴要放在主体内部的真实连接位置，并预留动作旋转时仍然相交的长度，不能只在静止姿势下勉强接触。

## 2. 高光属于材质和灯光

- 身体高光由 `roughness`、`clearcoat`、法线、灯光方向和曝光共同产生。
- 禁止用白色半透明球体充当身体高光。
- 眼睛高光属于表情图形，可以独立存在，但必须贴合眼球曲率且不能悬浮。
- 透明或胶质材质要控制 `depthWrite`、透明度和内外层关系，避免塑料壳感。
- 不用降低整个角色的 `opacity` 表达幽灵或透明：主体轮廓优先保持稳定，只让胶质外壳、鳍缘、尾迹或明确的内部结构选择性透光。
- 幽灵感不能只靠透明度：优先通过苍白低饱和主体、局部自发光、暗眼窝、边缘光和从实体连续溶解成尾烟的轮廓共同表达；实体核心仍需承受正常光影。
- 胶质外壳优先使用受控 `transmission`、厚度和衰减色，并保持可靠的深度写入；内部发光层与幽灵拖尾才关闭深度写入。
- 多个半透明球体不能互相套叠。需要内部结构时，外壳、内核和表面脉络必须各自承担清晰且不同的视觉功能。

## 3. 花纹不能变成贴块

- 大面积颜色变化优先使用顶点色、纹理或着色器。
- 必须使用几何时，花纹层要与主体同曲率、极薄且无可见侧壁。
- 鳞片、甲片、铆钉等真实立体结构可以凸起；普通色斑和光斑不可以。
- 真实物种花纹要保留其生态特征和身体分区。鱼类的背部、体侧和腹部通常不是同一色域，不能为了“丰富”随意换成高饱和陆生配色。
- 侧视合理的竖斑在俯视镜头下可能变成整圈“斑马纹”；顶点色应让条纹在体侧最强、背部中线减弱，并使用不等宽、不等距的自然节奏。

## 4. 游戏尺寸优先

- 先在正式棋盘尺寸和游戏相机下验收轮廓，再看细节放大。
- 每个角色只保留少量能在手机上读出的主细节，避免用大量小零件制造伪精致。
- 材质、颜色、轮廓和动作要共同表达物种与战斗职能。
- 建模前先确认章节生态与栖息地。海洋、陆地、飞行和幽灵单位的身体结构、肢体类型与运动方式必须匹配环境，不能只根据中文名称沿用错误物种模板。
- 功能信息与物种结构分开处理：例如“铁甲”由壳片和材质表达，“海龟”由扁甲、低头位、鳍肢和游动动作表达，不能用陆龟脚爪代替高防御感。
- 名称来自真实生物时，先提取玩家最熟悉、最强的物种轮廓信号，再叠加幻想设定。像“幽灵鲨”必须先由尖头纺锤体、三角背鳍、后掠胸鳍和分叉尾一眼读成鲨鱼，再通过颜色、轮廓光和灵体尾部表现幽灵感；不能让较冷门的真实银鲛特征盖过“鲨鱼”识别。
- 会正面朝向玩家的侧扁动物不能只用侧面轮廓挤出，否则游戏视角会变成薄板。主体应沿头、胸腹和尾柄建立多段连续截面，让正面、侧面和俯视都保持可信体积。

## 5. 动画必须由关节表达

- 移动、攻击和受击优先驱动头、肩、手、脚、尾、鳍等独立关节。
- 整体缩放只能作为辅助力度，不能代替真正的肢体动作。
- 血条、意图线和其他 UI 节点必须与动作骨架分离。

## 6. 验收检查

- 正面、侧面、背面和游戏视角都没有悬浮件、穿模或异常接缝。
- 材质高光随灯光变化，而不是固定贴在模型表面。
- 关闭小装饰后，主体仍能一眼识别物种和职业。
- 动作期间独立部位正确运动，UI 与接触阴影保持稳定。
