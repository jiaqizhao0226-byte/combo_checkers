# 技能稀有度升级系统 - 策划案 v1.0

> 目标：将原有的线性 Lv1→Lv5 升级体系改造为**稀有度池抽取**系统，
> 让每次三选一充满期待感，低概率出金色/紫色升级带来惊喜。

---

## 一、系统概述

### 1.1 核心变化

| 维度 | 旧系统 | 新系统 |
|------|--------|--------|
| 升级路径 | 固定 Lv1→Lv2→…→Lv5 | 从升级池中按稀有度概率抽取 |
| 每级效果 | 固定（Lv3=范围扩大等） | 同等级内有多种可选升级，效果各不相同 |
| 稀有度 | 装饰性（边框颜色） | **决定升级效果强度和类型** |
| 满级后 | 无事可做 | 解锁红色传说升级（额外强化/组合技） |
| 三选一体验 | 看技能名就知道效果 | 刷到金色升级 = 惊喜时刻 |

### 1.2 稀有度定义

| 稀有度 | 颜色 | 定位 | 效果类型 |
|--------|------|------|----------|
| 蓝色·普通 | `{100,180,255}` | 基础强化 | 小幅数值提升（+伤害、+范围、+持续） |
| 紫色·稀有 | `{180,100,255}` | 进阶强化 | 中幅数值提升 或 附加次要效果 |
| 金色·史诗 | `{255,200,50}` | 机制变革 | **改变技能机制**（新增玩法、质变效果） |
| 红色·传说 | `{255,60,60}` | 终极强化 | 满级后解锁；或融合为组合技 |

### 1.3 升级流程

```
玩家过关 → 三选一界面
                ↓
        从所有未满级技能的升级池中抽取
        每个候选 = (技能, 具体升级项, 稀有度)
                ↓
        选中后：该升级标记为已获得
        技能等级 = 已获得的升级数量
                ↓
        所有升级都获得 → 技能满级
                ↓
        满级后 → 红色传说升级出现在池中
```

## 二、概率系统

### 2.1 基础概率表（按游戏进度分段）

| 阶段 | 蓝色 | 紫色 | 金色 | 触发条件 |
|------|------|------|------|----------|
| 早期 | 75% | 20% | 5% | 第1章 s1-s5 |
| 中期 | 55% | 30% | 15% | 第1章 s6-s10 / 第2章 s1-s5 |
| 后期 | 40% | 35% | 25% | 第2章 s6+ / 第3章 |

> 红色传说不参与概率表，它只在技能满级后固定出现。

### 2.2 抽取流程

```lua
-- 伪代码
function PickOneUpgrade(skill, stage)
    -- 1. 获取该技能所有未获得的升级
    local pool = GetAvailableUpgrades(skill)
    
    -- 2. 如果技能已满级且红色未获得，直接返回红色
    if skill.allNormalTaken and not skill.legendaryTaken then
        return skill.legendaryUpgrade
    end
    
    -- 3. 按当前阶段概率Roll稀有度
    local rarity = RollRarity(stage)  -- 蓝/紫/金
    
    -- 4. 从池中筛选该稀有度的升级
    local candidates = FilterByRarity(pool, rarity)
    
    -- 5. 如果该稀有度没有可用升级，降级查找
    if #candidates == 0 then
        candidates = FindFallback(pool, rarity)
    end
    
    -- 6. 随机选一个
    return RandomPick(candidates)
end
```

### 2.3 保底机制

- **连续 5 次未出紫色以上**：下次紫色概率提升至 60%
- **连续 8 次未出金色**：下次金色概率提升至 30%
- **满级触发**：技能所有蓝紫金升级都获得后，红色传说**必定出现**在下次三选一中

## 三、技能升级池设计

### 设计原则

1. **每个技能有 8~12 个升级项**（蓝4 + 紫3~4 + 金2~3 + 红1）
2. **蓝色 = 线性数值增长**，拿多少个都不会质变
3. **紫色 = 更好的数值 + 附带小效果**，开始有实质性增强
4. **金色 = 机制改变**，让技能玩法产生质变
5. **红色 = 终极形态**，有组合技的形成组合技，没有的独立超强化

## 七、实现架构（技术方案简述）

### 7.1 数据结构变化

```lua
-- 旧结构
state.skills = { quake_land = 3, chain_lightning = 5 }

-- 新结构
state.skills = {
    quake_land = {
        upgrades = {
            "quake_aftershock",      -- 蓝·余震
            "quake_range_expand",    -- 紫·震域扩展
            "quake_crack",           -- 紫·地裂
        },
        level = 3,                   -- = #upgrades
        legendary = false,           -- 红色传说是否获得
    },
    chain_lightning = {
        upgrades = { ... },
        level = 9,
        legendary = true,            -- 雷震天罚已激活
    },
}
```

### 7.2 向后兼容

旧的 `Skills.Level(state.skills, id)` 和 `Skills.Has(state.skills, id)` 需要保持兼容：
- `Skills.Level()` 返回 `skill.level` 或 0
- `Skills.Has()` 返回 `skill.level > 0` 时的 level 或 nil

### 7.3 效果计算

每个技能的实际效果由其**已获得的升级组合**决定：

```lua
function Skills.GetEffects(owned, skillId)
    local data = owned[skillId]
    if not data then return {} end
    
    local effects = {}
    for _, upgradeId in ipairs(data.upgrades) do
        local upDef = Skills.UPGRADE_POOL[skillId][upgradeId]
        -- 累加效果到 effects 表
        ApplyUpgradeEffect(effects, upDef)
    end
    return effects
end
```

### 7.4 改造范围

| 文件 | 改动内容 |
|------|----------|
| `Skills.lua` | 新增 UPGRADE_POOL 表；重写 PickChoices；新增 GetEffects |
| `Battle.lua` | 所有读取技能等级/效果的地方改为读取 effects 表 |
| `GameUI.lua` | 三选一界面展示稀有度颜色/边框/特效 |
| `GameUI.lua` | 技能详情面板（长按查看升级树） |
